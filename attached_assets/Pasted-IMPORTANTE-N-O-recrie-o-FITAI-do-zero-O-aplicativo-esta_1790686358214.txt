==================================================

1. PRIMEIRO: DIAGNOSTICAR O PROBLEMA
    ==================================================

Antes de alterar o código, analise a implementação atual e descubra por que o MediaPipe deixou de reconhecer o corpo.

Verifique especificamente:

* inicialização da câmera;
* permissões da câmera;
* stream de vídeo;
* elemento ;
* resolução do vídeo;
* orientação do vídeo;
* canvas usado para desenhar landmarks;
* processamento dos frames;
* inicialização do MediaPipe Pose Landmarker;
* callback/resultados do MediaPipe;
* requestAnimationFrame ou mecanismo equivalente;
* transformação/crop/zoom aplicado ao vídeo;
* coordenadas dos landmarks;
* sincronização entre vídeo e canvas.

NÃO simplesmente substitua tudo.

Descubra primeiro onde a alteração quebrou o fluxo.

5. BOTÕES DE ZOOM

Adicionar um controle de zoom visível na interface da câmera.

Quero:

[ 0,5x ] [ 1x ] [ 1,5x ] [ 2x ]

O botão:

0,5x

é especialmente importante.

Quando o usuário tocar em 0,5x, o aplicativo deve tentar utilizar a câmera ultrawide real do celular, quando o dispositivo e o navegador permitirem.

IMPORTANTE:

0,5x REAL não deve ser simplesmente tratado como “zoom digital”.

No iPhone, quando o navegador permitir acesso às diferentes lentes, tentar selecionar a câmera ultrawide.

Porém, navegadores móveis nem sempre expõem diretamente a seleção de lente.

Portanto:

1. Detectar se existe uma câmera ultrawide disponível.
2. Se existir, permitir selecioná-la.
3. Se não existir, manter a câmera atual e informar que o dispositivo/navegador não disponibiliza 0,5x real.
4. NÃO fingir que o 0,5x é uma lente ultrawide se for apenas um crop/escala.

==================================================
6. FALLBACK PARA 0,5x

Se a câmera ultrawide real não puder ser acessada pelo navegador:

criar fallback visual.

Nesse caso, permitir reduzir/ampliar a área visível utilizando transformação adequada.

Mas deixar internamente claro:

“0,5x simulado”

e não:

“0,5x ultrawide”

quando não for uma lente real.

O fallback nunca pode prejudicar o MediaPipe.

==================================================
7. MUITO IMPORTANTE — ZOOM NÃO PODE QUEBRAR O MEDIAPIPE

O zoom/crop da interface não deve alterar incorretamente o frame que é enviado ao MediaPipe.

Preferencialmente:

* capturar o frame original da câmera;
* processar esse frame pelo MediaPipe;
* aplicar transformação visual separadamente na apresentação do vídeo/canvas.

Assim:

Câmera original
↓
MediaPipe
↓
Landmarks

E separadamente:

Câmera
↓
Zoom visual
↓
Tela

Não aplicar uma transformação que faça os landmarks perderem correspondência com a imagem.

Se o vídeo for transformado com CSS, garantir que o canvas de landmarks receba exatamente a mesma transformação.
